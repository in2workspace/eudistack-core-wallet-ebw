## [1.8.1] - 2026-06-03

### Fixed

- **`WellKnownCanonicalHandler`**: now accepts both `/.well-known/wallet-config-metadata` (direct/local) and `/business-wallet/.well-known/wallet-config-metadata` (CloudFront STG viewer-request rewrite) to resolve 404 in STG environments where ALB requires the `/business-wallet/*` path prefix.
- **`WellKnownWebFilter`**: removed shadow-path blocking of `/business-wallet/.well-known/wallet-config-metadata`. The Wallet PWA now uses this prefixed path as the canonical URL so the filter was incorrectly returning 404.
- **`VpEnvelopeSigner`**: added `jwk` (holder public JWK) and `kid` (RFC 7638 thumbprint) to the VP JWS header so verifiers can extract the holder identity without DID resolution.

## [1.4.0] - 2026-05-15

### Added

- **EUDISTACK-414 — Domain: operational-plane model and ports (US-03).** New bounded-context package `wallet.config.domain.model.operational`: sealed `OperationalConfig` interface (`permits DbTdeOperationalConfig` only — US-05/06/07 expand the `permits` clause when those Stories land); `DbTdeOperationalConfig` record with domain invariants enforced in a compact constructor (`columnEncryptionKeyArn` must start with `arn:aws:kms:`, `wrappedDek` must be non-null and non-empty, `algorithm` must be `"AES-256-GCM"`), defensive `byte[]` copy on construction and on accessor, redacted `toString()`, and `equals`/`hashCode` over `columnEncryptionKeyArn` + `algorithm` only (excluding `wrappedDek` to prevent timing-side-channel comparisons and keep secret material out of equality checks — AC-2b, E-16); `ActivationStatus` enum with kebab-case values (`active`, `pending-spi`) and a `fromValue()` resolver; `OperationalConfigDescriptor` aggregate record (root row + subtype combined) with a cross-field invariant mirror of the DB CHECK (`ACTIVE ⇒ connectivityVerifiedAt IS NOT NULL`, `PENDING_SPI ⇒ empty`); `OperationalAuditEvent` record (actor, event, plane, outcome, fieldChanges frozen list, correlationId, occurredAt) with `withSecretFieldRedacted(field, changed)` and `withPlaintextField` factory helpers (AC-4d); `ProbeResult` sealed interface with permitted subtypes `Ok(latencyMs)`, `Failed(reason)`, and `NotRegistered()`. Ports: `OperationalConfigPort` (`findActive() → Mono<Optional<OperationalConfigDescriptor>>` + `upsert()` + `canQuerySubtable(KeyManager)`); `OperationalConfigAuditPort` (`recordPermit` + `recordDeny` — append-only); `KeyManagerConnectivityPort` (`probe(KeyManager, OperationalConfig) → Mono<ProbeResult>`); `EnvelopeEncryptionPort` (`verifyCmkAccessible(cmkArn) → Mono<Void>` + `unwrap(wrappedDek, cmkArn) → Mono<byte[]>`). All domain types are pure Java — zero framework or infrastructure imports.

- **EUDISTACK-414 — Application: `OperationalConfigWriter` and `OperationalConfigReader` (US-03).** `ApplyOperationalConfigCommand` record (actor, keyManager, operationalConfig, correlationId, `Optional<Long> ifMatchVersion`). `OperationalConfigWriter` orchestrates the validate → probe → persist → audit flow: fast-fail validators (`validateKeyManagerSupported` rejects `key_manager != DB_TDE` with `UnsupportedKeyManagerException`; `validateOperationalConfigInvariants` checks domain invariants) run inside `Mono.fromCallable` so `onErrorResume` can intercept their synchronous throws and emit a DENY audit event before re-propagating (AC-4c, tech-design §3.4 fix-up `dab7c69`); connectivity probe runs outside the main DB transaction (KMS calls must not hold a DB lock); on `ProbeResult.Ok` the writer opens a `TransactionalOperator.execute` block — assembles the `OperationalConfigDescriptor` (`ACTIVE` status + `connectivityVerifiedAt = now()`), calls `upsert`, emits a PERMIT audit (`config.applied`) in a separate `REQUIRES_NEW` inner transaction; on `ProbeResult.Failed` / `ProbeResult.NotRegistered` emits a DENY audit (`connectivity.failed`) and throws `ProbeFailedException`; the top-level `onErrorResume` emits a DENY audit (`config.rejected`) for all other failures (optimistic lock, data integrity, domain ctor) without double-auditing `ProbeFailedException`. `OperationalConfigReader` delegates to `OperationalConfigPort#findActive()`. Application exceptions: `IncompleteOperationalConfigException`, `UnsupportedKeyManagerException`, `ProbeFailedException`.

- **EUDISTACK-414 — Infrastructure: R2DBC adapters, KMS adapter, and probe (US-03).** `OperationalConfigR2dbcAdapter` implements `OperationalConfigPort` using the default (tenant-aware) `DatabaseClient` — never the `publicSchema` pool (AD-1, enforced by ArchUnit). `findActive()` issues a single LEFT JOIN query across `wallet_operational_config` and `wallet_operational_config_db_tde WHERE is_active = true`. `upsert()` branches on `descriptor.version()`: version 0 → INSERT root row + sub-table row; version > 0 → resolves the existing row's `id` with `SELECT id ... WHERE is_active=true`, then UPDATE root with optimistic lock (`WHERE id=? AND version=?`) + UPDATE sub-table; zero updated rows → `OptimisticLockingFailureException`. `canQuerySubtable(DB_TDE)` issues `SELECT 1 FROM wallet_operational_config_db_tde LIMIT 1` as a defense-in-depth probe (an R2DBC error means the sub-table is absent, returns `false`). `OperationalConfigAuditR2dbcAdapter` implements `OperationalConfigAuditPort`; each call wraps the INSERT inside `auditTransactionalOperator.execute()` (a `REQUIRES_NEW` `TransactionalOperator` bean declared in `OperationalConfigBeans`) so that DENY records persist even when the outer writer transaction rolls back; `fieldChanges` is serialized to JSON by Jackson and bound via `::jsonb` cast so PostgreSQL validates the structure at insert time; a byte-array tripwire scans every `FieldChange.before`/`after` for the `[B@<hex>` pattern and throws `IllegalStateException` before any row is written if an unredacted `byte[]` leaks in (AC-4d). `KmsEnvelopeEncryptionAdapter` implements `EnvelopeEncryptionPort` using AWS SDK v2 `KmsAsyncClient` (dependency `software.amazon.awssdk:kms:2.31.78`): `verifyCmkAccessible` calls `kms:DescribeKey` wrapped in `Mono.fromFuture` with a configurable timeout (`wallet-ebw.probe.timeout-ms`, default 5 000 ms); `unwrap` calls `kms:Decrypt` and returns a defensive `byte[]` clone; CMK ARNs are never logged; all AWS SDK exceptions are translated to `KmsAccessException` with a functional message from `functionalMessage()` (class name + AWS error code if available; `TimeoutException` → `"probe timed out"` — AD-S2). `KeyManagerProbeRegistry` dispatches to `ProbeAdapter` implementations by `KeyManager`; `DbTdeProbeAdapter` executes the two-step probe (KMS CMK accessibility via `verifyCmkAccessible`, then sub-table accessibility via `canQuerySubtable`) inside a `Mono.using` Micrometer `Observation` span named `wallet.operational.probe` with low-cardinality key `key_manager=db-tde`; latency is measured with `System.nanoTime()` per subscription. `OperationalConfigBeans` `@Configuration` class explicitly wires all operational-plane beans (following the pattern of `WalletTenantConfigBeans`) including the `auditTransactionalOperator` `@Bean` with `REQUIRES_NEW` propagation.

- **EUDISTACK-414 — REST + application config (US-03).** `OperationalConfigController` maps three endpoints under `@RequestMapping("/admin/wallet-operational-config")` (external URL: `/business-wallet/admin/wallet-operational-config` via `spring.webflux.base-path: /business-wallet`): `POST` → 201 + ETag (`"<version>"`); `PUT` with `If-Match: "<N>"` → 200 + ETag (412 on version mismatch, 428 if `If-Match` absent, 400 if malformed); `GET` → 200 + ETag (404 if no active config). Actor is resolved from the reactive security context (UUID principal name from `JwtAuthenticationToken`). `X-Correlation-Id` is passed through or a UUID v4 is generated. Response DTOs: `OperationalConfigRequestDto` with `@ToString.Exclude` on `wrappedDek`; `OperationalConfigResponseDto` excludes `wrappedDek` and `columnEncryptionKeyArn` from the body (AC-2c). `OperationalConfigExceptionHandler` scoped `@RestControllerAdvice` maps: `IncompleteOperationalConfigException` / `UnsupportedKeyManagerException` → 409 (RFC 9457 `urn:eudistack:error:` URIs); `ProbeFailedException` / `KmsAccessException` → 424; `OptimisticLockingFailureException` → 412; `IllegalArgumentException` / `WebExchangeBindException` → 400; catch-all → 500. Feature flag `wallet-ebw.operational-plane.enabled: false` (default OFF — deploy-safe; future consumers gate on this property via `@ConditionalOnProperty`). Additional config properties: `aws.region` (`AWS_REGION`, default `eu-west-1`), `aws.endpoint-override` (nullable, for LocalStack), `wallet-ebw.probe.timeout-ms: 5000`, `wallet-ebw.kms.cmk-arn` (`WALLET_EBW_KMS_CMK_ARN`).

Creates: `wallet_operational_config` root table (UUID PK + `key_manager VARCHAR(16) NOT NULL` + `activation_status VARCHAR(16) DEFAULT 'pending-spi'` + `is_active BOOLEAN DEFAULT false` + `connectivity_verified_at TIMESTAMPTZ NULL` + `version BIGINT DEFAULT 0` + `updated_by` / `updated_at`; CHECK constraints: `chk_woc_key_manager IN ('db-tde','hybrid','hsm','qtsp')`, `chk_woc_activation_status IN ('active','pending-spi')`, cross-field `chk_woc_active_requires_probe` enforcing `active ⇒ connectivity_verified_at IS NOT NULL` / `pending-spi ⇒ connectivity_verified_at IS NULL`; partial unique index `uidx_woc_active_key_manager ON (key_manager) WHERE is_active=true`); `wallet_operational_config_db_tde` sub-table (PK = FK `config_id` ON DELETE CASCADE → `wallet_operational_config.id`; `column_encryption_key_arn VARCHAR(2048) NOT NULL`; `wrapped_dek BYTEA NOT NULL`; `algorithm VARCHAR(32) NOT NULL`; `chk_woc_db_tde_algorithm IN ('AES-256-GCM')` + `chk_woc_db_tde_wrapped_dek_not_empty CHECK (octet_length(wrapped_dek) > 0)`). ## [1.3.0] - 2026-05-13

### Added

- **EUDISTACK-413 — V3 migration: `chk_twc_server_requires_key_manager` CHECK constraint.** New forward migration `db/migration/V3__Server_requires_key_manager.sql` adds `ALTER TABLE public.tenant_wallet_config ADD CONSTRAINT chk_twc_server_requires_key_manager CHECK (NOT (wallet_mode = 'server' AND key_manager IS NULL))` — the counterpart of the `chk_twc_browser_no_key_manager` CHECK from V2 (EUDISTACK-412). Together they enforce the full wallet_mode/key_manager pairing invariant (`browser ⇒ key_manager IS NULL`, `server ⇒ key_manager IS NOT NULL`). This is the **primary enforcer of FR-21** in EUDISTACK-411: a seed SQL that attempts `wallet_mode='server'` with `key_manager=NULL` is rejected by PostgreSQL before any row is written. The migration is additive-safe (it is compatible with the pre-existing DOME `server`+`db-tde` row seeded in EUDISTACK-412 commit `ab2baa0`) and backward-compatible (no API change). Applied by `TenantSchemaFlywayMigrator#migratePublicSchema` on EBW startup. Reversible: `DROP CONSTRAINT IF EXISTS chk_twc_server_requires_key_manager`. Note: `db/tenant/V3__Wallet_config_audit.sql` is a different Flyway migration location (`db/tenant/`) and does not collide. Pre-deployment pre-check documented in the runbook. Implements EUDISTACK-411 US-02 (AC-2).
- **EUDISTACK-413 — Test coverage for the `server`+`db-tde` case.** Extended `WalletTenantConfigReadServiceTest` with two new server cases: `retrieveDescriptor_serverDbTdeTenantExists_returnsDescriptorWithKeyManagerPresent` and `retrieveDescriptor_serverTenant_forwardsNormalisedHostToPortUnchanged`. Extended `WalletTenantConfigDiscoveryControllerIT` with five new server cases: 200 with 4-field projection + explicit absence assertion for `key_manager`/`activation_status` (AC-1b, AC-1d, AD-1bis); uppercase Host → 200 (AC-1e); Host with port → 200 (AC-1e); unregistered server host → 404 opaque not cached (AC-5a, AC-5b). `WalletConfigArchitectureTest` (ArchUnit) passes unchanged — the read path is mode-agnostic; no new rules needed. ## [1.2.0] - 2026-05-13

### Added

- **EUDISTACK-412 — Wallet tenant discovery plane (read-only).** New public, session-less endpoint `GET /business-wallet/.well-known/wallet-config-metadata` that resolves the requesting tenant from the `Host` header and returns the 4-field projection `{wallet_mode, natural_persons_only, supported_credentials, version}` — `key_manager` is deliberately never exposed (AD-1bis). The response is cacheable on CloudFront with a 60-second TTL and an `ETag: "<version>"` (`Cache-Control: public, max-age=60`, `Vary: Host`); an unregistered host gets an opaque `404` (RFC 9457, `about:blank`, same timing as the `200`); a missing/blank `Host` header gets `400` (`urn:eudistack:error:missing-host-header`). EUDIW browser wallets can read their tenant mode from this plane instead of the build-time `WALLET_MODE` env var (build-time fallback on failure — the EUDIW consumer side is delivered by EUDISTACK-37). New `wallet.config` bounded context (hexagonal, read-only): `WalletMode` / `KeyManager` (kebab-case values) / `TenantWalletConfigDescriptor`; `WalletTenantConfigReadService`; `TenantConfigurationPort.findByHost`; an R2DBC read adapter that queries `public.tenant_wallet_config` exclusively through a `search_path=public` connection (`PublicSchemaConnectionFactory`) so the discovery path never touches a tenant schema (AD-1, enforced by ArchUnit). Implements EUDISTACK-411 US-01 (read side).
- **EUDISTACK-412 — Flyway migrations for the wallet discovery plane.** `db/migration/V2__Create_tenant_wallet_config.sql` creates `public.tenant_wallet_config` (`schema_name` PK + FK→`public.tenant_registry`, `host` NOT NULL UNIQUE + index, `wallet_mode`, `key_manager` nullable, `natural_persons_only`, `version`, `updated_by`/`updated_at`/`created_at`) with CHECK constraints `wallet_mode IN ('browser','server')`, `key_manager IS NULL OR key_manager IN ('db-tde','hybrid','hsm','qtsp')` (kebab-case), and `NOT (wallet_mode='browser' AND key_manager IS NOT NULL)` (FR-20) — these CHECK constraints are the primary enforcer of the wallet_mode/key_manager pairing rules (there is no on-write validation in the EBW; that belongs to EUDISTACK-55). `db/tenant/V3__Wallet_config_audit.sql` creates `<tenant>_business_wallet.wallet_config_audit` plus a `BEFORE UPDATE OR DELETE` append-only trigger — the table only; it is written by EUDISTACK-55, not by anything in EUDISTACK-411. (These tables belong with the EBW, which owns and migrates the `public` schema via `TenantSchemaFlywayMigrator`, as `tenant_wallet_config` is a sibling of `tenant_registry` — feature-design §4.2.)
